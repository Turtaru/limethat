# Folder application integration

## Ownership

- `src/lib/ui-kit/` is the canonical vendored library source. It contains actual Godenk components and shared, layered CSS, not showcase markup or compiled catalog assets. See its provenance note. Generic components have no routes, archive operations or persistence.
- `src/features/` owns routes, archive translation, media lifetimes, connection status, editors and supported settings. A single reactive `Session` owns the `Workspace` and route-keyed unsaved drafts. Editor pages can unmount during Back/Forward without losing fields, selected files, original conflict snapshots, or completed picture imports.
- `src/lib/archive*`, folder access, pictures and workspace remain the storage boundary. No server, storage mirror or additional API exists. A small workspace change keeps missing/damaged picture reads from disabling unrelated editing; permission failures still update connection state.
- Shared CSS retains semantic themes, page-colored details, timeline geometry and existing hover/focus states. Navigation follows the original screen prototype: a floating bottom dock with a contextual round action, 110px plus safe-area content clearance, and sticky search/detail toolbars. Focus uses existing border colors rather than external outlines; borderless actions retain underline/text feedback, and invalid fields retain their error border. No demo assets or generated showcase bundle are imported.

## Routes and screens

The Vite base stays `/limethat/`. Routes are `#/events`, `#/events/new`, `#/events/:uuid`, `#/events/:uuid/edit`, `#/labels`, `#/labels/new`, `#/labels/:id`, `#/labels/:id/edit`, and `#/settings`; `/` renders Events. Creation and editing are full pages, never dialogs. Reserved creation routes precede ID routes. A legacy string label ID named `new` is encoded in generated detail links to avoid that reserved segment. Search uses `?q=` inside the hash and replaces the current history entry without remounting the search field. Normal route clicks use the installed router's history handling, while modified clicks retain native behavior. The added branding/top navigation and visible Events/Labels headings are removed; their titles remain available to assistive technology. Return navigation restores saved scroll and attempts to focus the originating link. Unknown records/routes are explicit, and detail URLs remain intact while reconnecting a folder.

Events use archive ordering. Search includes title, body and embedded label titles. The Events timeline renders a full-year activity grid at each year boundary and a month grid below each month heading, using current search results. Label collections omit activity grids. Counts use exact dates only; month jumps offer actual dated months and focus the month heading rather than its preceding year overview. Partial dates are shown without inventing a day. All matching metadata is rendered; there is no new pagination control or server pagination contract. Pictures load near the viewport, with stable 4:3 layout, and are released on unmount/source change. Large-archive rendering performance remains unmeasured.

Details render body text safely, not executable HTML or remote Markdown images. Supported local picture references are displayed through deferred folder reads. The full-image viewer reads the original processed image; cards use thumbnails where available. Saved Android-compatible frames render through the existing read-only viewport. Event/label editor pages reuse `ImageFrameEditor` for positioning, fit and zoom; device/Android compatibility checks in `docs/image-framing.md` remain pending.

## Editing and preservation

The event editor uses native date inputs for full `YYYY-MM-DD` start/end dates, or blank values. The archive still reads legacy partial dates; editing one requires choosing a full date rather than silently converting it. Picture selection comes first, above title/name and all other fields in both editors. It lives in the bordered framing surface, not a separate visible file field. An empty frame opens the native picker; existing pictures expose Fit width, Fit height and Change image. Existing multi-picture events keep all their frames; changing an existing picture replaces its reference with a newly selected attachment, without deleting the old file. Existing local image references remain in the editable body; removal only removes references. Description and unknown Markdown are not reconstructed from a simplified view model. Event drafts retain existing frame entries and unknown embedded label properties, including labels absent from `tags.json`. New pictures start contained and can be repositioned before Save. Existing pictures load the original processed attachment, not a thumbnail; frame-only Save updates metadata without re-encoding or importing the attachment. Untouched legacy missing frames remain missing.

Label create/edit/delete uses existing archive propagation and conflict checking. Label pictures and frames are supplied as complete drafts; replacement initializes an independent frame that can be adjusted before Save, and explicit removal removes only the reference. Duplicate label names are not forbidden by storage; the UI does not invent a uniqueness rule. Label IDs are always compared using `labelKey`, never numeric conversion.

Saves validate dates before imports. Images use the existing 25 MiB processing limit and browser decoding support; no HEIC promise. Failed saves retain fields and file selections. Each draft remembers successful picture imports and per-File frames so retrying a record save does not reimport the same files. Preview preparation and later import share the same cached processed JPEG/thumbnail for an immutable File; failed processing is retryable and writes nothing. Save is disabled while preview preparation is pending. Object URLs are owned by the framing view and released after its consumers update or unmount. Cancel never removes attachments. The page's Cancel action discards that route's draft and replaces the URL with its detail/list destination; successful saves replace the editor URL with the saved record (or list when refresh failed). Back/Forward and dock navigation retain drafts for the session. File controls cannot be programmatically repopulated after remounting; their help text names the retained File selections. Reload/closing warns while any draft or operation exists, subject to browser restrictions. Drafts are not persisted across reloads. Folder replacement and app updates remain blocked until all drafts are saved/canceled.

Generic editor pages and overlay pickers accept an application-owned dock snippet. The page owns Save; a native picker/viewer owns Done/Reset while active, and the underlying page dock is hidden. Label/date pickers and the image viewer remain modal overlays; creation/editing do not use `showModal()`.

A completed mutation with failed refresh closes as saved and reports a refresh/reconnect warning, rather than offering another save. Partial-change failures retain the draft on its page but block that editor's retry; inspect reported files/backups, refresh, then reopen the on-disk record. There is no automatic rollback. Stale saves remain rejected by the archive boundary. Recovery actions are also available inside error dialogs so native modality does not hide them.

## Settings and offline shell

With no archive connected, Settings shows Open archive and Create archive, without navigation. With an archive connected, it shows Refresh archive and Close archive; the dock action also refreshes. Reconnect appears when permission is required. Close deletes only the remembered browser handle and clears the loaded session, leaving archive files and permission untouched; it is blocked while drafts or operations exist. If forgetting the handle fails, the archive stays connected and the error is shown. Settings also exposes connection warnings, a theme selector and an update action only when a new version is waiting. Only the theme preference is kept in localStorage; IndexedDB still contains only the remembered folder handle. No account, synchronization, background access, archive mirror or attachment cleanup is offered.

The Vite build hook writes `dist/sw.js` from all completed output files, including public files and every chunk. Its revision hashes asset names and contents. Installation precaches only that enumerated shell; fetch handling never writes arbitrary responses to caches and ignores external/private media. Navigation fallback is restricted to the app entry. Development and framing builds do not register a worker.

An updated worker waits. Settings enables Update and reload only with no retained draft or operation, and the worker refuses activation when another Limethat tab is open. Old shell caches are removed after activation. Folder availability, permission persistence, browser cache eviction and actual offline relaunch remain device-dependent. Installability depends on browser criteria; no custom install prompt is added.

## Review checklist (not executed)

Use a disposable archive copy.

1. With no archive, verify only Settings with Open/Create is visible. Connect and verify those actions switch to Refresh/Close. Close, reload, and verify the remembered handle is gone but files are unchanged. Close must be blocked while drafting/writing. Reconnect after permission revocation; a failed connection must retain the last successfully loaded archive.
2. Search without losing input focus; open an event, use Back/Forward, and check query, scroll and focus. Reload a UUID/label deep link and reconnect without changing its URL.
3. Review unknown, year-only, month-only, full and range dates; undated cards; text-only cards; multiple pictures; absent/damaged pictures; missing thumbnails; saved frames; both themes; narrow and wide screens.
4. Open creation/edit URLs directly and reconnect; check the editor is a page, not a dialog. Use Back/Forward and dock navigation while drafting; verify fields, selected files and imported-picture retry state survive. Save/Cancel should replace the editor route. Create/edit/delete events and labels; verify unknown metadata, large IDs, hidden frame entries, unknown Markdown and embedded label properties survive. Cancel must not delete attachments.
5. Trigger validation, stale snapshots, unreadable events, permission loss, partial writes and saved-with-refresh-failure. Verify clear recovery paths, no blind mutation retries and retained drafts.
6. Review native dialog focus/Escape, keyboard navigation, viewer controls, browser zoom and physical touch. Check drag/pinch/fit/zoom in both editor pages, draft Cancel/Back/Forward, and sequential Android frame round trips; these remain unverified.
7. Serve `dist/` over HTTPS/localhost, wait for shell readiness, disconnect and reload all routes. Inspect caches: app assets only. Reopen/edit the folder offline where permission allows.
8. Deploy a new build while drafting: verify no automatic activation. Finish/cancel, close other tabs, then update. Check base-path asset resolution and installation icons.

`checks/activity.test.ts` adds prepared (not executed) coverage for complete year/month grids, leap days, early/late years, filtered counts and partial-date exclusion.

`checks/ui-adapters.test.ts` adds prepared (not executed) coverage for complete-draft preservation, large IDs, duplicate embedded-label properties, date precision, and picture reference changes.

Type/build checks are not runtime, accessibility, filesystem-provider, offline or Android round-trip proof. Automated tests must not run without user instruction.
